# rxopen-morning —— 每日晨报(数据编排)

每日晨报:把天气、空气质量、每日新闻、打工日历、老黄历宜忌、历史上的今天 编排成一份出门前的**决策简报**(穿什么/带不带伞/有什么谈资/心情基调)。数据来自 [vikiboss/60s](https://github.com/vikiboss/60s) 开源项目(MIT License © Viki),数据版权归原项目及原始数据源所有。

**这是一个编排型 skill**:它本身没有命令,而是教 agent 把 `rxopen` 的多个查询命令组合起来,输出一份**决策简报**(穿衣/带伞/谈资/心情),而不是罗列数据。用户开 5 个 App 花 5 分钟才能拼出来的东西,这里 30 秒一份。

> ⚠️ 本 skill 不含 AUTO-GEN 命令块,不要对它跑 `rxopen skills gen rxopen-morning`。它的价值在编排逻辑,不在命令索引。

## 安装与运行

```bash
npx @renxqoo/rxopen-cli install  # 一键安装(同步全部 8 个 skill 到已装的 AI 工具发现目录)
# 或直接用(已全局安装)
rxopen life weather 上海 --json   # 晨报编排用到的命令之一
```

## 输出格式

本 skill **不直接产出 `{ok,data,meta}` JSON**,而是 agent 拉取多条 JSON 数据后,按固定模板渲染成一份**人类可读的简报**(类似晨报卡片)。每条底层命令仍是 JSON 统一输出,agent 内部解析后合成简报。

## 典型用法

```bash
# agent 收到"来份晨报"后,内部依次执行(每条都要 --json 拿结构化数据):
rxopen life weather 上海 --json     # 天气 + 空气质量(决定穿衣/出行)
rxopen daily --json                 # 每日新闻(挑 3 条做谈资)
rxopen moyu --json                  # 打工日历(离放假几天)
rxopen life lunar --json            # 老黄历宜忌(趣味点缀)
rxopen life today-in-history --json # 历史上的今天(彩蛋)
# → agent 合成一份晨报简报输出给用户
```

## 前置条件

- **无需登录**:全部公开数据,无鉴权。直接调用即可。
- 需要用户告知**城市**(天气命令的位置参数)。用户没说时问一句。
- 公共数据源可能限流(429),某源失败时跳过该模块(见错误处理)。

## 错误处理

- 某个数据源拉取失败(限流/网络) → **跳过该模块**,简报其余部分照常输出,在缺失处标注"(数据暂不可用)"。不要因为一个源失败就整份简报出不来。
- 城市未找到(`not_found`) → 问用户确认城市名。
- `rate_limited`(429) → 该模块跳过,提示稍后可重试。

## 工作流

收到"晨报/今天看什么"类请求后,按这个顺序拉数据(每步都要 `--json`,拿结构化数据自己拼):

### 第 1 步:天气 + 空气(决定穿衣/出行)

```bash
rxopen life weather <城市> --json
```

如果用户没说城市,**问一句**(位置是位置参数:`rxopen life weather 上海`)。

从返回里提取:
- `weather.temperature` / `weather.condition` —— 穿衣 + 是否带伞
- `weather.wind_power` —— 风大不大
- `air_quality.aqi` / `air_quality.quality` —— 要不要戴口罩
- `alerts[]` —— 有无预警(暴雨/高温/台风)

### 第 2 步:每日新闻(社交谈资)

```bash
rxopen daily --json
```

从返回的 `news[]`(string 数组)挑 **3 条**最值得知道的(政策/大事/科技),作为"今日谈资"。这些是和人聊天/开会破冰的社交货币。

### 第 3 步:打工日历(心情基调)

```bash
rxopen moyu --json
```

从返回里提取:
- `nextHoliday` / `countdown.toWeekEnd` —— 离放假/周末几天(打工人刚需)
- `today.isWeekend` / `today.isWorkday` —— 今天上不上班
- `progress.week.percentage` —— 本周进度

### 第 4 步:老黄历宜忌(趣味点缀,可选)

```bash
rxopen life lunar --json
```

提取 `taboo.day.recommends`(今日宜)、`taboo.day.avoids`(今日忌),挑 2-3 个贴切的。**注意:这是趣味点缀,不要渲染成迷信**——用轻松口吻("今日宜约饭"比"今日宜祭祀"好)。

### 第 5 步:历史上的今天(彩蛋,可选)

```bash
rxopen life today-in-history --json
```

从 `items[]` 挑 **1 条**有趣的(优先科技/文化类,避免太沉重的事件)。

## 输出模板

**严格按这个格式输出**(用户一眼能扫完):

```
☀️ <城市> · <星期> <日期>  <农历>
─────────────────────────────────
🌤 天气:<当前温度>° <天气状况>
   <最高温>°→<最低温>° | <风力> | 湿度<湿度>%
   穿搭:<agent 基于温度/风力的推理建议,如"短袖+薄外套">
   <如有雨/雪/预警 → ⚠️ 提醒带伞/注意安全>
   <如 AQI 差 → 😷 建议戴口罩>

📰 今日谈资
   1. <新闻标题1>
   2. <新闻标题2>
   3. <新闻标题3>

🐟 打工日历
   <今天是周几/是否上班> · 距周末还有<N>天 · 距<下个节日>还有<N>天

📜 今日宜:<宜1> <宜2>   忌:<忌1>
📅 历史上的今天:<年> <事件>
```

**推理增量是价值核心**:穿搭建议、带伞提醒、口罩建议——这些不是查出来的,是 agent 基于天气数据的**推理**。这是晨报比"开天气 App"有价值的原因。

## 个性化(可选,问一次即可)

如果用户第一次用,可以问:
- 城市(默认可问"你在哪个城市?")
- 有车否(有车 → 加 `rxopen life fuel-price` 油价模块)
- 海淘/出境否(是 → 加 `rxopen life exchange-rate` 汇率模块)

后续记住偏好,不用再问。
