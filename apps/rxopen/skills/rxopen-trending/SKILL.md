# rxopen-trending —— 多平台热搜交叉雷达(数据编排)

多平台热搜聚合:把微博、知乎、抖音、B站、小红书、百度、头条、懂车帝、夸克 9 个平台的热搜榜单拉到一起,做**语义去重 + 交叉验证**,找出"多平台同时在讨论的真全民热点",区分共识热点(全平台命中)vs 平台偏差话题。数据来自 [vikiboss/60s](https://github.com/vikiboss/60s) 开源项目(MIT License © Viki),数据版权归原项目及原始数据源所有。

**这是一个编排型 skill**:它聚合 9 个平台的热搜,做**语义去重 + 交叉验证**,输出"真全民热点" vs "平台偏差话题"。单个热搜 App 只能给你它自己的榜单,**没有任何一个 App 能告诉你"微博和抖音同时在讨论、知乎在做深度分析"的某个话题**——这个交叉视角是编排型 skill 独有的护城河。

> ⚠️ 本 skill 不含 AUTO-GEN 命令块,不要对它跑 `rxopen skills gen rxopen-trending`。价值在交叉验证逻辑。

## 安装与运行

```bash
npx @renxqoo/rxopen-cli install  # 一键安装(同步全部 8 个 skill 到已装的 AI 工具发现目录)
# 或直接用(已全局安装)
rxopen hot weibo --json           # 编排用到的命令之一(单个平台热搜)
```

## 输出格式

本 skill **不直接产出 `{ok,data,meta}` JSON**,而是 agent 并发拉取多条热搜 JSON 数据后,做语义去重 + 交叉验证,按分级模板渲染成一份**人类可读的热搜雷达报告**。每条底层命令仍是 JSON 统一输出,agent 内部解析后合成报告。

## 典型用法

```bash
# agent 收到"全网在吵什么"后,内部并发执行(每条都要 --json):
```

用户也可指定平台:"微博和抖音对比" → 只拉 weibo + douyin。

## 前置条件

- **无需登录**:全部公开数据,无鉴权。直接调用即可。
- 无需用户额外信息(热搜是全国性的,不依赖城市/个人)。
- 公共数据源可能限流(429),某平台失败时跳过该平台(见错误处理)。

## 错误处理

- 某个平台拉取失败(限流/网络) → **跳过该平台**,其余照常交叉验证,在报告里标注"(XX 平台暂不可用)"。覆盖平台数相应减少。
- 全部平台失败 → 报错,提示稍后重试。
- 某平台返回空数组 → 该平台本轮无热搜,跳过。

## 工作流

### 第 1 步:并发拉取多平台热搜

用户想看几个平台就拉几个(默认拉全部 9 个)。**每条命令独立,可并发**:

```bash
rxopen hot weibo --json        # 微博
rxopen hot zhihu --json        # 知乎
rxopen hot toutiao --json      # 头条
rxopen hot douyin --json       # 抖音
rxopen hot bili --json         # B站
rxopen hot rednote --json      # 小红书
rxopen hot baidu-hot --json    # 百度
rxopen hot dongchedi --json    # 懂车帝
rxopen hot quark --json        # 夸克
```

**用户可指定平台**:"看下微博和抖音的热搜对比" → 只拉 weibo + douyin。

每个返回是数组,核心字段是 `title`(热搜标题)。各平台额外字段见 `references/platform-fields.md`。

### 第 2 步:语义去重 + 交叉验证(核心,这是价值所在)

把所有平台的 `title` 汇总,做**语义聚类**(不是精确匹配!):

- **同一事件**的不同表述归一类(如"某某明星离婚"微博版标题、"某某夫妇分手"知乎版标题 → 同一话题)
- 判定依据:关键词重叠 + 语义相似 + 实体(人名/事件名)一致
- LLM 做这个判断是强项——不要试图用字符串匹配,要用语义理解

每个聚类记录:
- `topic` —— 归纳出的统一话题名(你起的,简洁准确)
- `platforms` —— 哪些平台命中了这个话题(如 `["weibo","douyin","zhihu"]`)
- `hitCount` —— 命中平台数
- `perPlatform` —— 各平台该话题的标题原文(用于归纳讨论角度差异)

### 第 3 步:分级输出

按 `hitCount` 分级:

| 级别 | 条件 | 含义 |
|------|------|------|
| 🔥🔥🔥 全民共识 | 命中 ≥ 5 个平台 | 真·全民热点,几乎所有人都在看 |
| 🔥🔥 多平台热点 | 命中 3-4 个平台 | 确实火,但有小平台没跟 |
| 🔥 局部话题 | 命中 2 个平台 | 值得关注,可能有平台圈层属性 |
| 📌 平台独有 | 命中 1 个平台 | 可能是平台偏差/垂直话题/水军 |

### 第 4 步:归纳讨论角度差异(进阶,体现编排价值)

对 🔥🔥🔥 和 🔥🔥 级别的话题,用各平台该话题的标题/描述**归纳"不同平台的讨论侧重点"**:

- 微博:偏情绪宣泄、当事人回应、吃瓜
- 知乎:偏深度分析、专业人士解读、争议探讨
- 抖音:偏二创、玩梗、视觉传播
- 小红书:偏穿搭模仿、生活方式、种草/避雷
- B站:偏吐槽、鬼畜、深度视频
- 头条/百度:偏新闻资讯、官方报道

这个"同事件不同平台视角"的分析是**单平台热搜绝对给不了的**。

## 选平台策略

| 用户说 | 拉取哪些 |
|--------|---------|
| "全网热搜"/"汇总热搜" | 全部 9 个 |
| "微博热搜" | weibo |
| "微博和抖音对比" | weibo + douyin |
| "社交平台热搜" | weibo + zhihu + douyin + rednote + bili |
| "搜索引擎热搜" | baidu + toutiao + quark |
| "垂直社区" | zhihu + bili + dongchedi |

## 易踩坑

- **不要字符串匹配去重**:"XX离婚声明"和"XX夫妇和平分手"是同一事件,必须语义判断。这是编排的核心难点,也是 LLM 的强项。
- **各平台标题风格差异大**:微博短、知乎长(带问句)、抖音口语化。聚类时看**实体和事件**,不是字面词。
- **水军/营销内容**:微博热搜含推广(上游已过滤大部分,但偶有残留),百度热搜有商业词条。命中 ≥ 3 平台的才信,单平台独有的要提醒"可能带偏差"。
- **时效性**:热搜变化快,拉取的是调用时刻的快照,简报里标注时间。

## 适用场景

- **自媒体选题**:找多平台共识热点 = 确定能火的选题(自带流量验证)
- **舆情监测**:品牌/事件跨平台热度追踪
- **吃瓜群众**:一眼看懂"今天全网在吵什么",不用刷 9 个 App
- **内容运营**:找各平台差异视角,做差异化内容(知乎深度 + 抖音二创)
